# File Integrity Monitor жобасын зерттеу

## 1 Жоба туралы жалпы мәлімет

File Integrity Monitor немесе FIM — файлдардың бастапқы күйін сақтап, кейінгі күйімен салыстыру арқылы олардың өзгергенін анықтайтын қауіпсіздік құралы. Жүйе файл мазмұнының хэшін, файл көлемін, соңғы өзгертілген уақытын және орналасқан жолын тіркейді.

Бұл жобаның негізгі нәтижесі — бақыланатын каталогтағы өзгерістерді нақты уақытта анықтайтын Java консольдік бағдарламасы.

## 2 Мәселенің өзектілігі

Маңызды файлдар зиянды бағдарлама, рұқсатсыз пайдаланушы немесе кездейсоқ әрекет салдарынан өзгеруі, жойылуы немесе басқа файлмен ауыстырылуы мүмкін. Өзгерістер уақытында байқалмаса, жүйенің қалыпты жұмысы мен ақпараттың тұтастығына қауіп төнеді.

FIM бастапқы сенімді күйді базаға сақтайды. Кейін файл өзгерген сайын оның жаңа хэші есептеліп, бастапқы хэшпен салыстырылады. Хэштер сәйкес келмесе, жүйе тұтастық өзгерісі туралы оқиға жасайды.

## 3 Жобаның мақсаты

Java тілінде таңдалған каталогтағы файлдардың құрылуын, өзгертілуін және жойылуын нақты уақытта анықтайтын, файлдардың SHA-256 хэштерін SQLite базасында сақтайтын және өзгеріс табылған кезде пайдаланушыға ескерту беретін бағдарлама әзірлеу.

## 4 Жобаның міндеттері

1. Пайдаланушыдан бақыланатын каталог жолын қабылдау.
2. Каталог пен ішкі каталогтарды бастапқы сканерлеу.
3. Әр файлдың SHA-256 хэшін есептеу.
4. Файл туралы ақпаратты SQLite базасына сақтау.
5. WatchService арқылы каталогтағы оқиғаларды бақылау.
6. Жаңа файлдың құрылғанын анықтау.
7. Өзгертілген файлдың жаңа хэшін бұрынғы хэшпен салыстыру.
8. Файлдың жойылғанын анықтау.
9. Оқиғаларды SQLite базасына және журналға жазу.
10. Өзгеріс анықталғанда консольде ескерту шығару.
11. Негізгі компоненттер үшін кемінде 10 JUnit 5 тестін дайындау.

## 5 Зерттеу нысаны мен пәні

**Зерттеу нысаны:** файлдық жүйедегі файлдардың тұтастығын бақылау процесі.

**Зерттеу пәні:** Java WatchService, SHA-256 хэштеу алгоритмі және SQLite деректер базасы арқылы файл өзгерістерін анықтау әдістері.

## 6 FIM жұмыс алгоритмі

1. Бағдарлама іске қосылады және конфигурацияны оқиды.
2. Пайдаланушы бақыланатын каталогты көрсетеді.
3. DirectoryScanner каталогты рекурсивті сканерлейді.
4. HashService әр файлдың SHA-256 хэшін есептейді.
5. FileRepository файл күйін SQLite базасына жазады.
6. DirectoryWatcher барлық каталогтарды WatchService жүйесіне тіркейді.
7. CREATE, MODIFY немесе DELETE оқиғасы түскенде файл қайта тексеріледі.
8. Жаңа күй базадағы күймен салыстырылады.
9. Өзгеріс расталса, EventLogger оқиғаны тіркейді және AlertService ескерту береді.
10. OVERFLOW оқиғасы пайда болса, каталог толық қайта сканерленеді.

## 7 Бақыланатын оқиғалар

| Оқиға | Мағынасы | Жүйенің әрекеті |
|---|---|---|
| ENTRY_CREATE | Жаңа файл немесе каталог пайда болды | Хэш есептеу, базаға қосу, жаңа каталогты бақылауға тіркеу |
| ENTRY_MODIFY | Файл мазмұны немесе атрибуты өзгерді | Debounce кейін хэшті қайта есептеп салыстыру |
| ENTRY_DELETE | Файл немесе каталог жойылды | Жойылу оқиғасын журналға жазу |
| OVERFLOW | Оқиғалар кезегінде жоғалу болды | Толық қайта сканерлеу және базамен салыстыру |

## 8 Таңдалған технологиялар

| Технология | Міндеті | Таңдау себебі |
|---|---|---|
| Java 17 | Негізгі бағдарламалау тілі | Ұзақ мерзімді қолдауы бар тұрақты нұсқа |
| Maven | Жобаны жинау және тәуелділіктерді басқару | Стандартты каталог құрылымы және CI-ге ыңғайлы |
| WatchService | Файлдық жүйе оқиғаларын бақылау | Java стандартты кітапханасына кіреді |
| MessageDigest SHA-256 | Файл хэшін есептеу | Стандартты және кең қолданылатын криптографиялық хэш |
| SQLite | Файл күйлері мен оқиғаларды сақтау | Бөлек серверді қажет етпейді, бір файлда сақталады |
| SQLite JDBC | Java мен SQLite байланысы | JDBC интерфейсі арқылы SQL орындауға мүмкіндік береді |
| JUnit 5 | Автоматты тесттер | Maven және Java жобаларына жақсы біріктіріледі |

### Негізгі кластар

| Класс | Жауапкершілігі |
|---|---|
| Main | Бағдарламаны іске қосу және компоненттерді байланыстыру |
| MonitorConfig | Каталог, база және журнал параметрлерін сақтау |
| DirectoryScanner | Бастапқы және қайта сканерлеуді орындау |
| DirectoryWatcher | WatchService оқиғаларын қабылдау және өңдеу |
| HashService | Файлды блоктармен оқып, SHA-256 есептеу |
| FileRepository | SQLite базасындағы файл жазбаларымен жұмыс істеу |
| IntegrityService | Сақталған және жаңа күйлерді салыстыру |
| EventLogger | Оқиғаларды базаға және мәтіндік журналға жазу |
| AlertService | Пайдаланушыға ескерту көрсету |

## 10 Деректер базасының бастапқы схемасы

```sql
CREATE TABLE files (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    path TEXT NOT NULL UNIQUE,
    sha256 TEXT NOT NULL,
    file_size INTEGER NOT NULL,
    last_modified INTEGER NOT NULL,
    status TEXT NOT NULL,
    scanned_at TEXT NOT NULL
);

CREATE TABLE events (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    file_path TEXT NOT NULL,
    event_type TEXT NOT NULL,
    old_hash TEXT,
    new_hash TEXT,
    detected_at TEXT NOT NULL,
    message TEXT
);
```

## 11 Функционалдық талаптар

- каталог жолын командалық жолдан қабылдау;
- каталогтың бар және оқуға қолжетімді екенін тексеру;
- ішкі каталогтарды рекурсивті бақылау;
- бастапқы файлдар тізімін және хэштерін жасау;
- CREATE, MODIFY, DELETE оқиғаларын анықтау;
- өзгертілген файлды хэш базасымен салыстыру;
- оқиғаларды уақыт белгісімен сақтау;
- консольде түсінікті ескерту көрсету;
- қате жағдайларын өңдеу;
- пайдаланушы тоқтатқанға дейін үздіксіз жұмыс істеу.

## 12 Функционалдық емес талаптар

- Windows және Linux жүйелерінде жұмыс істеу;
- үлкен файлдарды жадқа толық жүктемей, блоктармен хэштеу;
- SQL сұрауларында PreparedStatement қолдану;
- SQLite базасын бақыланатын каталогтан бөлек сақтау;
- қайталанатын MODIFY оқиғаларын debounce арқылы біріктіру;
- журналда құпия файл мазмұнын сақтамау;
- компоненттерді жеке тестілеуге ыңғайлы архитектура қолдану.

## 13 Техникалық тәуекелдер және шешімдер

| Тәуекел | Салдары | Ұсынылатын шешім |
|---|---|---|
| Бір өзгеріске бірнеше MODIFY оқиғасы келуі | Қайталанатын ескертулер | 300–500 мс debounce қолдану |
| Файл жазылып жатқан кезде хэштеу | Қате немесе уақытша хэш | Қысқа кідіріс және бірнеше retry қолдану |
| WatchService оқиғалары жоғалуы | Өзгеріс байқалмай қалуы | OVERFLOW кезінде толық қайта сканерлеу |
| Жаңа ішкі каталог тіркелмеуі | Оның файлдары бақыланбайды | CREATE кезінде каталог болса, рекурсивті тіркеу |
| Үлкен файлдар өнімділікті төмендетуі | Жүйе баяулайды | BufferedInputStream және блоктық оқу |
| База файлының өзі бақылануы | Шексіз MODIFY оқиғалары | Базаны бөлек каталогта сақтау немесе exclude ережесі |
| Символдық сілтеме циклі | Шексіз рекурсия | Әдепкіде symbolic link-терді қумау |

## 14 MVP шекарасы

Бірінші жұмыс істейтін нұсқаға мыналар кіреді:

- консольдік интерфейс;
- бір негізгі каталог және оның ішкі каталогтары;
- CREATE, MODIFY, DELETE оқиғалары;
- SHA-256 салыстыру;
- SQLite базасы;
- консольдік ескерту;
- мәтіндік және деректер базасындағы журнал;
- кемінде 10 тест.

JavaFX интерфейсі, email, Telegram және жүйелік tray хабарламалары MVP аяқталғаннан кейін ғана қарастырылады.

## 15 Тестілеу жоспары

1. Бірдей файлдар үшін хэштердің тең болуын тексеру.
2. Өзгерген файл үшін хэштің өзгеруін тексеру.
3. Бос файл хэшін есептеуді тексеру.
4. Жоқ файлды хэштеу кезіндегі қатені тексеру.
5. Жаңа файлды базаға қосуды тексеру.
6. Файл жазбасын жаңартуды тексеру.
7. Файлды жойылған деп белгілеуді тексеру.
8. CREATE оқиғасын өңдеуді тексеру.
9. MODIFY оқиғасын өңдеуді тексеру.
10. DELETE оқиғасын өңдеуді тексеру.
11. Exclude ережесін тексеру.
12. OVERFLOW кейін қайта сканерлеуді тексеру.

## 16 Бірінші аптаның нәтижесі

- жоба тақырыбы мен мәселесі анықталды;
- FIM жұмыс принципі зерттелді;
- Java 17, Maven, WatchService, SHA-256, SQLite және JUnit 5 таңдалды;
- функционалдық және функционалдық емес талаптар жазылды;
- архитектура мен деректер базасының бастапқы схемасы дайындалды;
- тәуекелдер мен оларды азайту жолдары анықталды;
- GitHub репозиторийінің бастапқы құрылымы жасалды.

## 17 Келесі кезең

Келесі кезеңде Maven жобасы толық конфигурацияланып, HashService, бастапқы DirectoryScanner және SQLite қосылымы жүзеге асырылады. Осы компоненттерге алғашқы unit-тесттер жазылады.
